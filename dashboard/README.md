# ФК — дашборд производства

Отдельный веб-сервис, который показывает аналитику по данным бота ФК.
Живёт на вашей ВМ (виртуальная машина), крутится в Docker, наружу смотрит через nginx.

## Главное про безопасность данных

Сервис **не пишет в базу и не может этого сделать**. Три уровня защиты:

1. Соединение открывается с `default_transaction_read_only=on` — PostgreSQL отбивает
   любой `INSERT/UPDATE/DELETE/CREATE/DROP/TRUNCATE` ошибкой `25006`.
2. В коде стоит guard `_assert_read_only()` — выполняются только `SELECT` и `WITH`.
3. В сервисе физически нет ни одного SQL-запроса на запись, нет миграций,
   нет `CREATE TABLE IF NOT EXISTS`. Только два `SELECT` (см. `sources.py`).

Плюс `statement_timeout` (по умолчанию 15 с), чтобы тяжёлый запрос не подвесил базу,
и кеш на стороне сервиса — в базу ходим раз в `CACHE_TTL` секунд независимо от
числа открытых вкладок.

Бот (`bot.py` в корне репозитория) не изменён ни на строку.

## Режимы источника данных (`SOURCE_MODE`)

| Режим  | Что делает | Когда нужен |
|--------|-----------|-------------|
| `db`   | Прямой коннект к PostgreSQL, только чтение | ВМ видит базу по сети (основной вариант) |
| `api`  | Тянет готовый `/api/dashboard/all` бота по ключу | База закрыта, но HTTP бота доступен |
| `demo` | Локальный `demo_data.json`, к базе не обращается | Проверить деплой и nginx, не трогая прод |

## Деплой на ВМ

### 0. Что должно быть на машине

```bash
docker --version && docker compose version   # Docker и плагин compose
nginx -v                                     # nginx
```

Если Docker не стоит (Ubuntu/Debian):

```bash
curl -fsSL https://get.docker.com | sh
sudo apt-get install -y nginx
```

### 1. Забрать код

```bash
sudo mkdir -p /opt && cd /opt
sudo git clone https://github.com/HR-analyze/fk_analiz.git
cd /opt/fk_analiz/dashboard
```

### 2. Настроить `.env`

```bash
cp .env.example .env
nano .env
```

Минимум, что надо заполнить для боевого режима:

```ini
SOURCE_MODE=db
DATABASE_URL=postgresql://USER:PASSWORD@HOST:5432/DBNAME?sslmode=require
TIMEZONE=Europe/Moscow
CACHE_TTL=60
REFRESH_SECONDS=60
EXCLUDE_DATES=2026-09-01
PLAN_UPLOAD_TOKEN=<длинная случайная строка>
```

`DATABASE_URL` — та же строка подключения, что у бота на Relax Dev.
Если панель отдаёт хост/порт/юзера по отдельности, строка собирается так:
`postgresql://<user>:<password>@<host>:<port>/<database>?sslmode=require`.

> Если база на Relax Dev слушает только внутреннюю сеть — прямого коннекта с ВМ не будет.
> Тогда переключись на `SOURCE_MODE=api`, укажи `BOT_API_URL` и `BOT_API_KEY`
> (тот же `DASHBOARD_API_KEY`, что задан у бота).

### 3. Сначала прогнать на демо-данных

Чтобы убедиться, что контейнер и nginx живые, ещё не подключаясь к боевой базе:

```bash
SOURCE_MODE=demo docker compose up -d --build
curl -s localhost:8090/health
```

Ожидаем `{"ok": true, "mode": "demo", ...}`.

### 4. Переключить на боевые данные

```bash
docker compose down
docker compose up -d --build        # теперь читает SOURCE_MODE из .env
docker compose logs -f --tail=50
```

В логах должно быть:
`snapshot refreshed: production=… pauses=… mode=db`

### 5. nginx

```bash
sudo cp nginx/rate-limit.conf /etc/nginx/conf.d/fk-dashboard-rate-limit.conf
sudo cp nginx/fk-dashboard.conf /etc/nginx/sites-available/fk-dashboard.conf
sudo nano /etc/nginx/sites-available/fk-dashboard.conf   # подставить свой server_name
sudo ln -s /etc/nginx/sites-available/fk-dashboard.conf /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

Проверка: `curl -I http://<домен-или-IP>/` → `200 OK`.

### 6. HTTPS (если есть домен)

```bash
sudo apt-get install -y certbot python3-certbot-nginx
sudo certbot --nginx -d dashboard.example.ru
```

### 7. Файрвол

Наружу нужны только 80/443. Порт 8090 слушает **только localhost** (см. `docker-compose.yml`),
поэтому мимо nginx к сервису не достучаться.

```bash
sudo ufw allow 80,443/tcp && sudo ufw enable
```

## Обновление

```bash
cd /opt/fk_analiz && git pull
cd dashboard && docker compose up -d --build
```

## Что показывает дашборд

Фильтры: период (даты от/до), оборудование, продукт, **сотрудник**, смена
(день 08:00–20:00 / ночь 20:00–08:00) и **час суток**. Фильтры комбинируются.

- 6 KPI: операций, выпуск (шт), средняя длительность, средняя производительность,
  число простоев, коэффициент использования = работа / (работа + простои)
- Выпуск по дням, производительность по часам (штуки распределяются по минутам операции)
- Выпуск по оборудованию, топ продуктов, **выпуск по сотрудникам**
- Простои по причинам (круговая), работа vs простои (кольцевая)
- Сводка фактов — текстовая выжимка, она же попадает в PDF
- Сводка по дням карточками: выпуск крупно, доля от лучшего дня полоской,
  план с процентом выполнения, операции, средняя длительность и простои
- **Сводка по сотрудникам**, сводка по оборудованию, тайминги по продуктам,
  **план/факт по позициям**, детализация операций

### Клик по графику = фильтр

Столбцы графиков, карточки дней и строки таблиц кликабельны: нажатие применяет
соответствующий фильтр, повторное нажатие по тому же значению — снимает его.
Активные фильтры показаны чипами под панелью фильтров, каждый снимается крестиком,
`Сбросить всё` возвращает период по умолчанию.

Зона нажатия шире самого столбца (вся колонка графика) — на телефоне попадать пальцем
не нужно точно в столбик.

### План / факт

Панель под фильтрами показывает План, Факт, Выполнение и Недобор по позициям,
ниже — таблица «План / факт по позициям» с сортировкой по величине отставания.

Файл плана — рабочий шаблон Excel. Читаются четыре колонки, находятся по заголовку:

| Колонка шаблона | Что берём |
|---|---|
| `Сокращенное название` | продукт (совпадает с названием в базе бота) |
| `Оборудование` | линия |
| `План количество` | план в штуках; пустые и нулевые строки пропускаются |
| `Дата план` | дата плана |

⚠️ В шаблоне `Дата план` — формула `=$H$1`, а `H1` — `=TODAY()`. Если Excel не
сохранил вычисленное значение, дата приходит пустой. Поэтому рядом с кнопкой
загрузки есть поле **Дата плана** — она подставляется во все строки без даты.
Проверяй её перед загрузкой.

Планы накапливаются: повторная загрузка перезаписывает только те даты, что
пришли в файле. Хранятся в `PLAN_FILE` (по умолчанию `/app/data/plans.json`),
каталог примонтирован томом — переживает пересборку контейнера.
**База бота при этом не используется вообще.**

Загрузка защищена отдельным ключом, потому что сам дашборд публичный:

```ini
PLAN_UPLOAD_TOKEN=$(openssl rand -hex 24)
```

Пока ключ пустой, кнопка загрузки выключена и `POST /api/plan/upload` отдаёт 403.
Ключ спрашивается один раз и запоминается в браузере.

Недобор считается **по отстающим позициям**, а не как общее сальдо:
перевыполнение по одной номенклатуре не закрывает провал по другой.
Если план загружен не на все дни периода, под заголовком появляется
предупреждение — иначе сравнение вводит в заблуждение.

### Выгрузки

**Excel по виджету.** У каждой панели в шапке кнопка `⤓ Excel` — выгружает данные
именно этого графика или таблицы **с текущими фильтрами**. Кликнул по столбцу →
фильтр применился → нажал выгрузку → в файле только отфильтрованные данные.
Отдельный лист «Фильтры» фиксирует, что было применено и когда,
а имя файла содержит период и фильтры: `fk_detail_2026-09-02_2026-09-08_Glimek.xlsx`.

Кнопка `Excel: всё` в шапке страницы кладёт все виджеты листами в одну книгу.

**PDF всей сводки.** Кнопка `Скачать PDF` собирает документ: KPI, сводку фактов,
все графики (включая линию средней по часам), план/факт и таблицы. Файл строится
на сервере через reportlab, кириллица — шрифтом DejaVu, поэтому образ ставит
`fonts-dejavu-core`.

**Сводка фактов** — блок на странице и в PDF: итоги, дни с максимумом и минимумом,
топы по продуктам, оборудованию и сотрудникам, часы ниже средней, простои по
причинам, отставания по плану. Только числа и доли: причины простоя названы ровно
так, как их записал бот, без домыслов о том, что за ними стоит, и без рекомендаций.

### Провалы по часам

На графике «Производительность по часам» пунктиром отмечена средняя за период.
Часы ниже неё окрашены красным, их количество вынесено в подпись графика —
сразу видно, где проседаем.

### Скрытие отдельных дат

Переменная `EXCLUDE_DATES` (через запятую, формат `YYYY-MM-DD`) убирает дни из отчёта:
они не попадают ни в KPI, ни в графики, ни в справочники, ни в детализацию.
**База при этом не меняется** — записи остаются на месте, фильтр работает только на чтении.
Убери дату из списка и перезапусти контейнер, чтобы она снова появилась.

```ini
EXCLUDE_DATES=2026-09-01
```

### Мобильная версия

- Панель фильтров свёрнута, в заголовке видно, какие фильтры активны
- KPI в две колонки, графики с укрупнёнными подписями (часть подписей прореживается)
- Таблицы превращаются в карточки «поле → значение» — горизонтального скролла нет
- Все нажимаемые элементы не меньше 44px
- Нажатия обрабатываются через `pointerup`, а не `click`: в мобильных браузерах
  `click` с не-интерактивных элементов (SVG-столбцы, строки таблицы) доходит до
  обработчика не всегда. Движение пальца больше 12px считается скроллом, а не нажатием

Страница сама обновляется каждые `REFRESH_SECONDS` секунд, в базу при этом ходит
не чаще `CACHE_TTL`. Графики нарисованы на чистом SVG — внешние CDN не нужны,
дашборд работает и в закрытом контуре без интернета.

## API сервиса

| Метод | Назначение |
|-------|-----------|
| `GET /` | сама страница |
| `GET /health` | 200 пока сервис может отдать данные, 503 если снимка нет |
| `GET /api/meta` | справочники, границы дат, режим источника |
| `GET /api/summary?date_from=&date_to=&equipment=&product=&employee=&shift=&hour=&refresh=1` | все показатели |
| `GET /api/plan` | что загружено: даты, число позиций, включена ли загрузка |
| `POST /api/plan/upload` | загрузка xlsx (multipart `file`, опционально `date`), нужен `X-Plan-Token` |
| `DELETE /api/plan?dates=YYYY-MM-DD,...` | удалить планы на даты, нужен `X-Plan-Token` |
| `GET /api/export/xlsx?widget=<виджет|all>&<те же фильтры>` | выгрузка виджета в Excel |
| `GET /api/export/pdf?<те же фильтры>` | вся сводка в PDF |

Виджеты для `widget=`: `kpi`, `daily`, `hourly`, `equipment`, `products`,
`employees`, `reasons`, `work_vs_stop`, `plan`, `employee_timings`,
`equipment_timings`, `product_timings`, `detail`, либо `all` — все листами.

## Если что-то не так

| Симптом | Куда смотреть |
|---------|--------------|
| `docker compose logs` пишет `DATABASE_URL is not set` | не заполнен `.env` или он не подхватился (`env_file: .env`) |
| `OperationalError: connection refused` / таймаут | ВМ не видит базу: файрвол на стороне Relax Dev, неверный хост/порт → пробуй `SOURCE_MODE=api` |
| `password authentication failed` | неверный логин/пароль в `DATABASE_URL` |
| `bot API rejected the key (401)` | `BOT_API_KEY` не совпадает с `DASHBOARD_API_KEY` бота |
| В логе `startup options rejected by the server` | нормально: база за пулером, сервис сам перешёл на `SET`, read-only сохранён |
| Страница есть, но пусто и жёлтый баннер | проверь `curl localhost:8090/health` на ВМ |
| Кнопка «Загрузить план» серая | не задан `PLAN_UPLOAD_TOKEN` в `.env` |
| «не нашлось ни одной строки с заполненным планом» | колонка «План количество» пустая во всём файле |
| План загрузился не на ту дату | в шаблоне `Дата план` — формула без сохранённого значения; выстави поле «Дата плана» перед загрузкой |
| Планы пропали после пересборки | нет тома `./data:/app/data` в `docker-compose.yml` |
| В PDF вместо кириллицы квадраты | в образе нет `fonts-dejavu-core`; пересобери с `--build` или задай `REPORT_FONT` |
| Выгрузка Excel скачивает не то, что на экране | файл строится по фильтрам из URL запроса — сверь лист «Фильтры» в книге |
| 502 от nginx | контейнер не поднялся: `docker compose ps`, `docker compose logs` |

## Закрыть доступ, если публичность передумаешь

Дашборд по умолчанию открыт всем, у кого есть ссылка. Закрыть — двумя строками в nginx
(закомментированные блоки лежат прямо в `nginx/fk-dashboard.conf`):

```bash
# по паролю
sudo apt-get install -y apache2-utils
sudo htpasswd -c /etc/nginx/.htpasswd fk
# добавить в server{}:  auth_basic "FK dashboard";  auth_basic_user_file /etc/nginx/.htpasswd;
sudo nginx -t && sudo systemctl reload nginx
```
